# 比邻中央组网

## 控制端与客户端

控制端对外提供 HTTPS Web 地址，并开放配置服务端口。以下命令在本机启动控制端，将同进程内的网关作为单个转发节点。

```sh
bilin-web \
  --config-server-protocol tcp \
  --config-server-port 22020 \
  --gateway-peer-url tcp://127.0.0.1:22020 \
  --gateway-relay-data
```

部署时，把 `--gateway-peer-url` 换成设备可达的节点地址。如果配置服务和 HTTPS Web 使用不同的主机名，通过 `--config-server-host` 指定配置服务主机。

- `/#/admin` 是管理员端。已有的默认管理员需要先在控制台修改默认密码，才能进入管理员端。
- `/#/workspace` 是用户端。首页可单独绑定设备、创建网络或向已有网络添加设备。创建时勾选「同时添加设备」可以一次完成建网和入网，可选名下设备或输入新设备的八位编号。新设备需先启动客户端完成登记。
- 没有绑定设备的账号登录后会打开五步新手引导。左下角会勾选已完成的步骤，箭头跟随当前查看的步骤，点击该行即可继续。进度保存在当前浏览器的账号下。打开客户端的「设备与控制端」，在「设备身份」里找到八位设备编号。绑定后在第四步选择已有网络。账号还没有网络时，此步会提供创建表单。第五步确认设备加入选中的网络。当前下载步骤显示提示文字。
- GUI 在「配置服务器」填写控制端 HTTPS 地址，保存后每次启动都会自动登记。命令行使用 `bilin-core --controller https://control.example.com`。本机可用 `http://127.0.0.1:11211` 做验证。
- 桌面客户端可在「设备与控制端」选择「登录并绑定本机」，使用系统浏览器和现有 Web 账号绑定。浏览器已登录时会显示当前账号供确认。系统打开浏览器失败时，可复制客户端显示的登录链接并手动打开，客户端会自动同步绑定结果。授权后，浏览器会弹出加入网络窗口，可以选择已有网络、新建并加入，或稍后加入。仍可在 Web 使用客户端显示的八位编号手动绑定。Web 删除设备后，运行中的客户端会清除已绑定账号并恢复登录入口。
- 安卓访问端在应用内使用 Web 账号登录或注册，并自动绑定当前设备。账号只有一个可用网络时直接尝试连接，多个网络时可以选择。后续启动会尝试连接上次选择的网络。点击「断开连接」会在当前运行期间停止自动连接。控制台删除设备后，应用会恢复登录首页。
- 客户端身份保存在应用数据目录，命令行可用 `--state-dir` 明确指定。保留同一份数据即可在升级和重启后沿用设备 ID。不同安装应使用不同数据目录。

控制端在首次登记时分配设备编号，碰到重复编号会重新生成。升级会保留原有设备归属和网络成员关系。后台分别显示设备心跳、配置通道和网络实例状态。管理端可为已登记的设备指定归属。用户解除绑定时，设备会被移出该用户的全部网络。

用户可以在网络详情选择「添加设备」，选择自己已绑定的设备，或输入新设备的八位编号同时绑定并加入网络。按编号添加新设备时，设备需登记在线且未绑定其他账号。

删除设备会撤销设备归属和所有网络权限。设备已经加入网络时，需要先确认删除。客户端下次心跳会沿用原编号，以未绑定状态重新登记。后台的设备间路径根据客户端上报的路由显示直连、节点中转或两者都有。

## 独立转发节点

在管理员端填写节点名称和设备可访问的 TCP 地址，例如 `tcp://node.example.com:22020`。后台签发节点注册码后，在对应服务器上启动节点进程。

```sh
# 由服务配置安全地注入 BILIN_NODE_TOKEN。
bilin-web --node-controller https://control.example.com \
  --node-listen 0.0.0.0:22020 --node-udp --node-quic --node-kcp
```

原生 UDP 使用与 TCP 相同的端口。QUIC 和 KCP 分别使用注册 TCP 端口加一、加二的 UDP 端口。WSS 可通过 `--node-wss-bind 127.0.0.1:22025` 和 `--node-wss-url wss://node.example.com/_bilin/relay` 接入，公网入口由持有可信证书的反向代理提供。节点确认监听成功后，控制端才会下发对应的协议地址。

独立节点向控制端登记并同步网络。控制端启用独立节点时，可省略内置网关参数。使用多个节点时，绑定后的客户端按控制端下发的列表测速。控制端下发唯一接入节点。直连失败时尝试一个备用节点，之后按测得延迟选择转发路径。节点跨网段部署时，各节点也需要能访问彼此的公开地址。

双成员网络使用双方到候选节点的延迟之和选择共同转发节点。多成员网络按设备分配接入节点，优先保住已建立的直连，仍需转发的流量可以经过节点互联。

首个版本使用 TCP 探测节点端口。设备换节点时保留原虚拟 IP，切换需要重新建立连接。

客户端和节点可通过 `BILIN_STUN_SERVERS` 配置 NAT 探测地址，逗号分隔，使用 `主机:端口` 格式。通过 `BILIN_STUN_UDP_FALLBACK` 可补充仅提供 UDP 的探测服务。设备的网络需要允许访问这些地址才能取得探测结果。

## 用户管理

账号默认使用 TCP。开启「智能协议路由」后优先使用健康的原生 UDP，劣化时按链路质量择用 KCP 或 QUIC，最后在可用的 TCP 和 WSS 中择优。正常连接会持续使用，恢复到更高优先级协议需要稳定观察。

「强制中转」和「强制协议」互斥。强制中转期间只走节点的 TCP 连接，强制协议只允许指定协议。在账号列表点击「恢复默认」解除限制，原来的智能协议勾选状态继续生效。封禁会停止账号的组网并拒绝登录，解封后设备会恢复原来的网络成员关系。

管理员可以在「用户管理」的「更多」菜单设置强制策略、封号、解封和删除账号。确认删除后，账号会退出登录，名下网络及访问权限会被删除，设备会退网并解除绑定。设备保留原编号，可绑定到其他账号。当前登录账号和内置管理员账号受删除保护。
